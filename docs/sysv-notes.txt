Notes on the Sysv/GASNet prototype implementation status
Jason Duell <jcduell@gmail.com>

The big idea: is to set up shared memory between processes on the same node, so
we skip using the network for gets/puts.   I also created a "sysVnet", which
runs Active messages between processes using shared memory.  This was needed for
the SMP conduit, but should be faster than using a network API, so we should
keep using it for processes which share memory.

Implementation big picture:  we need to set up lots of shared memory, make it
work with whatever network API is being used, set up SysVnet, and then make sure
that shared memory is used for gets/put/AM when possible.

Setting up shared memory
    - right now the smp code uses mmap/fork, but this won't work when we don't
      have control over process spawning (i.e. for most network conduits).
    - So you need to switch to use Posix mmap and/or SysV, depending on OS.
        - POSIX shared memory works on most of our OSes;  AIX doesn't support
          it, but does support large System V shared memory segments.  
        - Ideally, you can use come autoconf checks, and prefer Posix shmem if
          available, then (MAP_SHARED | MAP_NOSYNC) if available (it's not in
          many places, except some BSD variants), followed by SysV shmem if
          nothing else works.  Or it may devolve into OS-specific checks--i.e.
          case (AIX)...--but I don't think so.
        - Cygwin may be a whole different story:  we might have to do some
          Win32-specific stuff if the Cygwin API doesn't support any of the Unix
          ways of setting up shared memory.  
    - I *believe* that we can generally set up the shared memory, and then
      register the area with whatever network pinning/registration API the
      conduit uses, but this may vary by network?
    - placement of shared area--may matter for symmetric pointers
        - only an issue on Altix and related systems
        - talk to Dan about this.

- Making sure shared memory is used when available
    - Gets/puts: switch to use local ptr already implemented?
        - I can't remember if I only implemented it for SMP or not.  The logic
          should be quite similar to that for pthreads:  there's a table that
          gets filled with node indexes, with an offset for shared memory
          regions this thread can access, or zero if remote.
    - Active Messages:  I also can't remember if my solution was general or SMP
      conduit specific, but the idea is just to send local calls to SysVnet, or
      else using the gasnet conduit's AM.
